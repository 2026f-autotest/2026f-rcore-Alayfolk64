# 实验一：多道程序与 trace 系统调用

## 实现

本实验在 ch3 分支实现 `sys_trace`。请求 0 从当前应用的地址读取一个字节，请求 1 写入 `data` 的低 8 位，请求 2 查询当前任务调用指定系统调用的次数。未知请求及非法内存地址返回 -1；未调用过的系统调用计数为 0。

每个任务的 `TaskControlBlock` 保存独立计数器，覆盖本章支持的 write、exit、yield、get_time 和 trace。系统调用入口先增加计数，再执行分派。因此查询 trace 次数时，本次查询已经计入；其他任务的输出和调度不会污染当前任务的统计。记录计数的可变借用在函数返回时释放，不会跨越任务切换。

本章尚未启用分页，应用直接使用物理地址。内存检查允许当前应用的加载区域以及它自己的用户栈，拒绝其他地址。用户栈由内核单独分配，不能只检查 `APP_BASE_ADDRESS` 以上的应用加载区。读写使用单字节 volatile 操作，使内核写入能够由用户程序实际观察到。

## 调度与状态

yield 在统计之后将任务从 Running 变为 Ready，再选择下一个 Ready 任务；退出同样先统计，再把状态改为 Exited。计数保存在任务控制块中，所以被抢占或主动让出 CPU 不会丢失历史次数。

## 验证方法

在 ch3 分支提交上述实现和本报告，由仓库原有的固定版本测试及 QEMU 评测。检查 `ch3_trace` 对时间调用、yield、write 和 trace 自身计数的断言，并验证用户栈字节读写及代码地址读取；同时检查本章其余应用的回归结果。评测输出、通过数量和报告检查以本次 Actions 生成的真实结果为准。
